# Проверка безопасности GitHub Pages

Проверка относится к статическому сайту `supernovvvvvachuu-droid/vibe-resale`: объявления читаются из открытых GitHub Issues и добавляются к локальному каталогу. Рабочая версия до исправлений — коммит `4aa8fda11da8d6b668b7066bbb8ca76c6dc7f1a2`.

## Подтверждённые проблемы

1. **Проверялся уже изменённый адрес покупки** — `js/listings.mjs`, функция `readListing`. До проверки разрешённых адресов код вызывал `new URL`, затем удалял query и fragment. Такой порядок скрывал явный порт `:443`, кодирование имени хоста и параметры переадресации от строгой проверки `validatedExternalUrl`. Исправление: проверять исходную строку, принимать только прямые HTTPS-адреса разрешённых площадок, не исправлять опасный адрес молча.
2. **Ошибка одного элемента прерывала загрузку всех объявлений продавцов** — `js/listings.mjs`, функции `readListing` и `sellerItems`. Не проверялись типы `issue`, `title`, `body` и форма ответа API; один исключительный элемент прерывал `issues.map`. Основной статический каталог сохранялся благодаря `catch` в `js/api.mjs`, однако объявления остальных продавцов терялись. Исправление: проверять входную структуру и пропускать некорректные записи отдельно.
3. **Не было предела продолжительности загрузки** — `js/listings.mjs`, `sellerItems`. Цикл пагинации не имел верхней границы, а запросы — тайм-аута. Недоступный ответ или слишком большой поток Issues мог задержать показ каталога. Исправление: ограничить запросы по времени и числу страниц, безопасно обрабатывать ошибку источника.

Эти выводы не означают, что злоумышленник мог записать произвольный код в репозиторий через Issue: запись Issue и изменение файлов репозитория — разные права GitHub.

## Что уже сделано безопасно

- Название, описание, размер, состояние и подписи проходят экранирование `escapeHTML` в `js/core.mjs` и `e` в `js/components.mjs` / `js/views.mjs`. Пользовательский Markdown или HTML не вставляется как исполняемый HTML.
- Фотографии проходят `safeImagePath`; произвольные `javascript:`, `data:` и внешние трекеры не становятся `src` карточки.
- Страница вещи повторно проверяет адрес покупки через `validatedExternalUrl`. Внешняя вкладка открывается с `rel="noopener noreferrer nofollow"`.
- Статический сайт не принимает пароль, платёжные данные или авторизационный токен для чтения публичного каталога. Публикация через Issues требует входа на стороне GitHub.

Безопасные участки не переписывались ради аудита.

## Проверки публичных файлов

Проверены отслеживаемые текстовые файлы исходной версии и структура `catalog.json`. Приватные ключи, типичные GitHub-токены, AWS access keys и литералы JWT по проверенным шаблонам не обнаружены. В каталоге нет таблиц пользователей, сессий, приглашений или служебных настроек. Имена фотографов в `assets/credits.json` относятся к публичным лицензионным сведениям.

Поиск по шаблонам не доказывает отсутствие любого возможного секрета. Если ключ когда-либо публиковался, одного удаления файла недостаточно: ключ нужно отозвать у его поставщика.

## Локальная проверка

Проверки находятся в `tests/`. Они используют вымышленные локальные примеры, а не опубликованные объявления. `tests/render-security.test.mjs` проверяет экранирование вредоносного текста в карточке и странице вещи, блокировку опасных `src` / `href`, рабочие ссылки Avito и Telegram, защиту `noopener` и сохранение подсчёта результатов тестов по стилю.

Запуск без сторонних зависимостей:

```sh
node --test --test-isolation=none tests/*.test.mjs
```

## Границы защиты GitHub Pages

У GitHub Pages нет прикладного сервера: браузер проверяет объявления, но не может установить продавцу роль или провести серверную модерацию. Сайт не следует внешним ссылкам при проверке и не может гарантировать дальнейшее поведение Avito или Telegram. Такие гарантии не имитируются.

В исходной версии нет Content Security Policy. Совместимая политика могла бы дополнительно ограничить выполнение скриптов и источники загрузки, но её нельзя добавлять вслепую: фотографии вложений GitHub используют перенаправления на служебные CDN, а политика не должна ломать реальные изображения. HTTP-заголовки `frame-ancestors`, HSTS и `X-Frame-Options` также нельзя надёжно подменить HTML-метатегом.
